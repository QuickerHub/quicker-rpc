# QuickerAgent 产品设计

QuickerAgent 是面向 Quicker 动作维护与工作区任务的 Agent 工作台。用户在同一会话中提出需求、查看工具进度、处理审批，并通过已有资源与浏览器面板检查结果。产品当前能力与可用范围见 [产品功能地图](../docs/product/README.md)。

## 工作台体验

主界面沿用 Quicker V2 Agent 工作台的视觉设计：平坦的中性灰深浅主题、紧凑窗口栏、左侧工作区与会话导航，以及居中的对话内容和输入区。

参考源为 Quicker 仓库的 `QuickerPc/Quicker.Headless/Web/src/features/agent/sdk/AgentShell.tsx`、`features/agent/agent-workspace.css` 和 `src/theme.css`；迁移的是 Agent UI SDK 的布局与视觉约定，功能范围仍由本产品的能力地图定义。

- 顶栏高 36px，展开侧栏宽 240px；正文与输入区共享最大 960px 的内容轨道。
- 对话正文为 14px，代码为 12px；主界面、菜单、浮层与设置共用黑白灰主题 token，选中、焦点与发送按钮使用单色对比。深浅主题均可读，状态提示与代码高亮保留语义色。
- 新会话将输入区与引导内容居中；窗口较矮时内容可滚动，输入与发送操作保持可达。
- 已有会话、工具消息、审批、输入与侧面板保留各自行为。界面迁移不改变 Agent/Ask/Launcher 的权限含义。
- 设置、资源、浏览器与小窗快捷入口继续打开已有功能；工具测试与发布预览遵守现有开发/调试门控。

主工作台布局限定于 `agent-workbench` 作用域；通用配色在主题根节点定义，让挂在 `body` 下的浮层保持一致。Launcher 的透明窗口与动作设计器的独立主题继续遵循各自的使用场景。

## 扩展原则

工作台为后续功能保留清晰的组合边界：外壳承载导航与主区域；会话框架组合标题、消息、审批、输入和 dock。业务组件继续使用现有会话、工具、持久化与执行服务。

快捷入口通过声明式功能定义描述名称、目标和可用条件，再由界面绑定已有面板、命令或路由。新增入口必须对应可用能力；界面定义不授予工具权限，也不替代运行时 capability 判断。

DeepSeek Harness 的布局组合和静态描述与运行状态分离是架构参考。工作台仍使用现有 AI SDK Agent 内核与消息流，扩展入口的工程约定见 [Agent 架构](../docs/agent-architecture.md#工作台组合边界)。

默认生产已经采用静态 React 界面、独立 Node Agent service 与薄 Electron 壳，构建、启动、
Electron prepare 和发布入口默认选择该组合。它们复用同一 API、AI SDK loop 与用户资料格式，
不为切换宿主另建会话、执行或存储实现。Next.js 保留开发 HMR 和显式 legacy 生产入口。

启动前核验当前 shell 的运行模式与产物标记；静态产物缺件或模式不匹配时明确失败，不根据
遗留文件静默换用其它宿主。模式选择不等于安装包已完整更新，也不保证事务式升级。
生产入口的工程切换不代表安装/升级、真实旧资料与完整宿主业务已全部验收；会话、审批、
Launcher 和 Designer embed 继续保持原交互，并按实际能力验收。迁移门槛见
[架构目标](../docs/agent-architecture.md#框架去耦与目标运行边界)。

## Agent 运行与会话原则

- Agent、Ask、Launcher 和命令限制由最终可执行能力集共同约束；界面选择或子代理不能扩大父任务的权限。显式禁用所有工具与未配置工具是两种状态。
- Ask 当前不开放浏览器工具：现有观测调用也可能启动 runtime 或创建会话；须先提供只连接已有会话、无导航与宿主启动副作用的观测端口，再按能力逐项开放。Agent 模式保留浏览器能力。
- Ask 读取已有本地项目和已连接宿主，不自动导出、补空、修补元数据或启动 Quicker。
  依赖自动启动的远端查询/恢复能力暂不提供；失败保留真实结果，并说明手动连接或切 Agent。
  设计器上下文只保留已明确给出的目标，实时标题和选中步骤不可用时如实说明。
- 停止操作属于当前运行，会取消它的模型、压缩与派生工具工作，并释放该运行拥有的连接。切换会话允许原会话继续在后台执行，不等同于停止。
- 会话运行状态、用户草稿、工作台布局和工具展示各有唯一 owner；展示方式改变不应丢失正在运行的任务、审批或未保存内容。
- Agent 与手动动作 trace 按每次运行展示，切会话或工作目录不串事件，也不重新执行动作。关闭已启动的页签只结束观察；无法确认原生终态时显示“结果未知”，历史重放不启动实时订阅。观察失败与原生执行结果分别保留，后续已确认结果可以纠正未知状态。派发前已明确拒绝的请求显示原失败；启动确认丢失时不自动重试。
- 隐藏面板不能抢占全局快捷键；菜单和弹层应支持键盘进入、关闭和焦点恢复。
- 已访问的工作区文件由工作台持有实例。切文件、浏览器/trace、折叠 dock、切聊天或工作区
  只改变呈现，保留 Designer/属性草稿、撤销与正在进行的保存；显式关闭或删除对应项目
  才释放实例。隐藏弹窗保留原选择，不能恢复原已取消的删除选项。
- 文件读写固定所属工作区及路径；旧读取/保存回执不能更新新实例。删除仅关闭该项目的
  文档，保留其它项目的草稿。将步骤加入对话时，目标是当前可见聊天。
- 历史消息编辑属于当前会话；切换后保留其草稿，隐藏会话不响应前台的 Esc 或外部点击。
  分支确认只针对当时的消息、编辑锚点和草稿；期间会话或内容变化时，旧确认不能截断新历史。
- 读回已有历史、展示工具详情和准备模型上下文是不同投影，不为换皮另建一套 send、审批或历史存储协议。
- 清理临时工作区只删除该目录的本地文件；导出文件中的动作或子程序 ID 不构成宿主对象的所有权证明，不能据此自动删除 Quicker 内容。

长期重构的阶段、依赖和验收状态统一维护在 [产品计划](../docs/product/README.md#agent-与工作台持续重构)。这些原则是整改目标，不能据此宣称现有实现已经全部满足。

## 编写指南的来源

文档目录默认打开本地指南。Agent 显式请求当前 gateway 的 `program-source` 时，结果展示
本次读取的 gateway、codec 实现身份、支持格式和文档来源；缺失 metadata 标为未知，查询
失败显示不可用，不替换成本地正文或其它 gateway。格式声明只说明 codec，不证明宿主可写。

工具详情沿用既有展示，并可通过「在文档中打开」进入同一个文档面板。本地与不同 gateway
的同名主题分别保存其读取结果；打开已有结果不隐式刷新连接。迟到加载不能覆盖较新的
内容或失败状态。深浅主题下来源、格式和失败说明均可读，长身份值可换行。

## Quicker 原生 MCP 连接

用户于 2026-10-26 确认：在现有“设置 → Quicker 连接”卡片中提供本机原生 MCP 的发现、
检测和显式启用，不另建 MCP 管理器。此连接默认关闭；启用只保存本产品的来源引用，
不复制 token、URL 或 headers，也不修改 Quicker 的启用、写入和审批设置。

- 打开设置只读取当前配置和本机来源，不连接服务。明确点击“检测”才初始化此来源、
  读取完整工具目录后关闭；检测不会启用连接、调用业务工具或启动 Quicker。
- 用户配置、工作区覆盖、来源发现和本次检测结果分别显示。发现文件不表示服务可达；
  启用表示后续符合权限的 Agent turn 使用它。检测成功标为“本次检测成功”并附时间，
  不表示存在常驻连接、已核验宿主实例或具备动作写入权限。
- 来源按当前 `QUICKER_HOME` 或用户 `.quicker` 读取，不猜默认端口或依赖固定 V2 版本。
  Agent 的环境不证明等于 Quicker 的启动环境。来源缺失、关闭、非法或鉴权/同意失败
  明确显示，不创建 token、不修复宿主、不换用另一个地址。
- 只管理用户配置中的本机来源条目；保留其它字段和服务。当前工作区同名覆盖或已有
  同名自定义连接时明确说明，不覆盖这些设置，也不把用户开关保存说成已对该工作区生效。
- 配置读取、保存和检测固定 cwd、配置 revision 与请求代次。隐藏、切工作区或新请求
  取消旧观察；迟到结果不能覆盖新状态。保存确认丢失后重新读取，不自动重复写入。
- 服务当前 instructions 和工具 schema 随每轮连接重新取得；作为有来源的使用资料进入
  原 Agent/子代理流程，不能扩大最终工具权限。缺失、未知或超预算的说明不能补成已知。
- 每次发送前后核验配置与观察到的本地监听进程 PID/创建时间；变化后停止旧连接。
  该观察不能证明产品身份或同进程内的原生会话未重建，检查与连接之间仍有竞态。
  请求已派发后失败或目标变化明确标记结果未知，不能据此声称未写入或自动重放。
- 原生服务可能按客户端进程共享编辑工作集；不同聊天的新 SDK client 不证明编辑会话
  隔离。编辑应使用服务实际返回的明确 slot/目标并保留冲突与检查要求。本入口不宣称
  完成聊天隔离、统一 Designer 写回或 qkrpc/native 目标合并。

原生 MCP 和 qkrpc 的连接状态分开展示，保持现有黑白灰深浅主题、窄窗与键盘可用性。
界面和设置响应只接收脱敏状态，不接收认证内容。

## 范围与待确认决策

语音输入、语音聊天与剪贴板历史已移除，不属于工作台功能范围。

当前已实现的迁移覆盖主 Agent 工作台与已有功能入口。现有 V1 动作 YAML 流程通过 Agent 的 open/save 工具与原文件工具接入同一会话，沿用 CLI/MCP 的 bundle、基线和冲突保护；新版设计器首批组件已接既有文件编辑入口，完整迁移继续按清单验收。第三方动态 UI 插件和可替换 Agent 执行器尚无已确认的产品交互。

## 统一动作设计器（已确认目标，迁移中）

下一项界面交付搬入 Quicker 项目的新版动作设计器。复用其 React 组件、动作模型、步骤
catalog、编辑会话和 host bridge 语义；沿用本工作台的黑白灰深浅主题。通过 adapter 连接
V1/V2，展示和编辑组件不按版本复制。

- 一个兼容宿主可自动连接；多个宿主可用时明确选择，编辑会话展示并绑定目标。断连、重启
  或连接变化不能把未保存内容写到另一个实例。
- 载入完整动作，覆盖来源设计器已有的步骤/参数、变量、资源和嵌套结构；保留选择、撤销/
  重做、脏状态、校验与错误反馈。迁移按能力清单验收，不能只搬视觉外壳。
- 模块/动作/子程序 catalog 与外置脚本/默认值文件分别验收；保留 qkrpc 现有文件资源能力。
  连续多次编辑后，保存必须与当前可见文档一致，不能从陈旧的父组件副本写回。
- 编辑会话持有唯一文档 controller；人工与 Agent 修改进入同一文档版本流程，不各保留一份
  可静默覆盖对方的草稿。保存共用 storage identity、revision、宿主内存态保护和部分落盘反馈。
- Agent 继续使用现有单一 AI SDK loop 和权限。设计器的 UI catalog 可以读取 UI schema；
  Agent 仍使用压缩 step-runner schema，不通过迁移扩大工具权限。
- 先跑通已有通信契约的完整编辑链，再用真实负载研究传输效率；不为搬界面同时重写协议。

自动识别、双宿主、Agent 整合与通信优化的依赖/验收统一见 [主线计划](../docs/product/README.md#统一-rpc-与动作设计器当前主线)。

第一批实现已在既有磁盘动作编辑入口加入主程序/嵌入子程序页签、保留草稿与历史的
源码切换、实时完整快照和文档保存控制。连续编辑、未知字段/文件引用、外部冲突及
异步保存已通过隔离真实浏览器回归。Agent 已接入下述主动作备注编辑首片；完整
metadata/资源操作、宿主编辑会话与更完整的 Agent 协同仍按清单迁移。

步骤表单沿用来源设计器的大脚本参数页签：按 UI schema 的多行和语言/字段标识显示，
普通参数仍在原分区，脚本可在可编辑预览与完整页签间切换。两处保留同一个字段编辑器
和表单草稿，切换页签不提交文档；确认共用一次 Session 修改，取消沿用原放弃流程。
外置文件继续沿用现有文件写入和引用语义。页签支持方向键、Home/End，选择不随输入重置；
字段隐藏时回到参数页，切换文档和迟到 schema 不覆盖当前草稿。语言提示只进入 UI schema，
Agent 继续读取原压缩 schema。

主动作的设计器现在读取项目内已核验的目标记录，展示 V1/V2、版本和实例/会话/端点。
身份加载期间允许继续编辑；确认身份后才开放本地保存，不替换已有草稿或历史。旧未绑定
项目可保存到工作区，不能隐式继承当前宿主并同步；绑定变化会保留草稿并阻止覆盖。
普通 Save 只在本地比较完整目标记录和正文/属性基线；显式 Sync 才调用绑定宿主，并分别
报告正文、属性和本地版本是否确认。运行、调试、打开宿主编辑器和悬浮尚未接入文档目标，
在此入口暂不可用；删除项目只清理本地文件。其它入口的兼容行为保留。

Explorer 打开有效的 `program.source.yaml` bundle 时，使用实际 C# codec 的完整文档投影，
进入同一个 APDE、文档 Session、controller 和撤销历史；不创建 `data.json` 镜像。标题只读
取自已核验身份文件，来源目标显示实际动作 ID、V1/V2、版本、实例、会话和端点，并明确
当前宿主状态未核验。该记录与本地快照都不证明当前连接或写权限。
普通 Save 比较 YAML、资源、身份、checkpoint 与 codec 的完整字节快照，只保存本地正文，
不推进原生基线。重新打开后，从当前正文与原 checkpoint 计算本地待同步状态；与基线一致
也不表示当前宿主已同步。显式 Sync 沿用原 `action.save` 的离线 dry-run 与一次提交，按
实际收据核对版本、正文指纹和 storage identity，保留部分成功、结果未知及较晚的本地修改。
源码视图展示同一草稿经 C# 预览的只读 YAML；标题、说明、图标和外置资源暂为只读。
source 文档的 owner 跟随原文件实例，隐藏聊天仍保留；普通 Agent 文件写入和 source save
不能绕过它。缺少源码行号映射时关闭该入口的实时 pin，不增加 Agent 变量、Save/Sync 权限。
协议与支持边界见[源码包文档协议](../docs/authoring/source-bundle-document.md)。

主动作与嵌套编辑面共用该文档的 catalog port。模块列表、参数 schema、摘要、快速插入、
工具箱和子程序目录查询携带同一完整目标；身份尚未加载或项目未绑定时不查询远端。
切换文档或目标后，旧请求和缓存不能更新新文档，也不清除其草稿与撤销历史。目标失配、
断连或取消明确失败，不改查当前默认宿主或使用其它宿主的静态 schema。独立编辑入口
保留原兼容行为；完整资源操作、多宿主选择与更完整的 Agent 实时编辑继续迁移。

模块目录与参数定义没有可重验的 UI 来源 revision 时，每次读取都查询当前原生目录与
`get-ui`，只合并同一文档中同时进行的相同请求，不将已完成结果或浏览器持久缓存当作
当前定义。重新打开或恢复参数弹窗也重新读取；等待和失败保留人工草稿与历史，但不能
用旧成功确认或打开旧帮助链接。迟到及取消结果不能覆盖较新的读取，不增加后台轮询。
原生控制值按请求原样转发，未提供、空字符串、空白及大小写不同的值不合并。live 读取
失败不静默改用静态目录；独立开发入口仍可显式选择 static 模式。
定义刷新导致字段重新分组时保留原编辑实例和外置文件的待写内容。隐藏文档保留这些
owner，但字段的子浮层退出活动页面、全局录键与快捷键失活，不能覆盖或修改其它文档。

现有步骤复制粘贴入口读取当前 Session 的完整原文；所选分支、可核验的局部变量闭包与
必要内部子程序作为一次当前文档事务粘贴，保留未知字段和精确数值。整批先分配唯一身份
和名称，调用参数名按被调程序接口改写，绑定值按调用者变量改写；保留期间发生的其它
编辑，一次撤销恢复整批。复制与粘贴先提交现有表单草稿；隐藏后恢复、换 owner、新操作、
打开步骤弹窗或快速插入使旧异步回执失效，普通输入及 contenteditable 保留文字快捷键。

此剪贴板只支持已核对的有限本地模块语义：comment、delay、if、simpleIf、group、
evalexpression 与内部 subprogram；表达式限字面值、运算符和明确的字面变量访问。
该边界不代表当前连接提供了通用原生依赖证明，不增加 Agent 权限。其它模块、隐藏回调、
